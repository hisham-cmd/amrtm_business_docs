# سياسة أسرار المنصة

> هذه الوثيقة جزء من `amrtm_business_docs` **المشارك مع فريق التطوير**.
> لا يحتوي أي ملف في هذا المستودع على بيانات اتصال حقيقية.

---

## المبدأ

| النوع | مكانه | في Git؟ |
|---|---|---|
| القوالب (`*.example.cfg`) | المستودع | ✅ نعم |
| التوثيق والأدلة | المستودع | ✅ نعم |
| **بيانات الاتصال الحقيقية** | **خارج المستودع** | ❌ **لا** |
| **`.env` الإنتاج** | **على السيرفر فقط** | ❌ **لا** |
| **`APP_KEY` الإنتاج** | **على السيرفر فقط** | ❌ **لا** |

المستودع يشاركه كل من في فريق التطوير. أي سرّ يصل إليه يصبح معلناً
لمن يملك صلاحية قراءة — **ولا يمكن سحبه بعد `git push`**.

---

## ما يجب ألّا يدخل المستودع أبداً

| الملف | المحتوى الحسّاس |
|---|---|
| `ftp-credentials.cfg` | كلمة مرور FTP |
| `production-db.cfg` | كلمة مرور MySQL وكلمة مرور FTP |
| `prod-db-token.txt` | رمز الوصول لأداة استعلام الإنتاج |
| `.env` | `APP_KEY` وكلمة مرور قاعدة البيانات |
| `app.yaml` | `APP_KEY` + كلمات مرور النشر |
| `render.yaml` | كلمات مرور قاعدة البيانات |
| `*.pem` / `*.key` | مفاتيح SSL |
| `prod-db.php` المرفوع | رمز وصول حيّ |

## مستويات الحماية

### 1. `.gitignore` في كل مستودع

```gitignore
.env
.env.*
!.env.example
app.yaml
render.yaml
ftp-credentials.cfg
production-db.cfg
prod-db-token.txt
prod-db.php
*.pem
*.key
```

### 2. `global-gitignore.txt` (مُرفق هنا)

فعّله مرة واحدة لكل مشاريعك:

```bash
git config --global core.excludesfile /path/to/global-gitignore.txt
```

### 3. التحقق قبل النشر

```bash
# تأكّد أن لا سرّ في الملفات المتتبَّعة
git ls-files | while read f; do
  grep -lE "APP_KEY=base64:|DB_PASSWORD=.{6,}|FTP_PASS=.{6,}" "$f" 2>/dev/null
done
```

## قواعد التوليد

| السر | الأداة |
|---|---|
| `APP_KEY` | `php artisan key:generate --show` |
| كلمة مرور قوية | `openssl rand -base64 24` |
| رمز أداة الإنتاج | 32 حرفاً عشوائياً من `a-zA-Z0-9` |

**لا تُعد استخدام كلمة مرور موجودة في مكان آخر.** كل سرّ يجب أن يكون
فريداً — فاستعادة واحد يجب ألّا تفتح others.

---

## عند 발생 تسريب

1. **غيّر السرّ فوراً** من لوحة الاستضافة أو قاعدة البيانات.
   التغيير المتأخر يعني أن السرّ مكشوف طوال هذه الفترة.
2. `git rm --cached <file>` لإيقاف التتبّع.
3. أضفه إلى `.gitignore`.
4. **التاريخ لا يُمحى.** استخدم `git filter-repo` لإعادة كتابة التاريخ،
   أو ابدأ مستودعاً جديداً. وبالطبع، من كان لدى صلاحية قراءة قد يكون
   حفظ نسخة.

> **القاعدة:** إذا كان السرّ قد دُفع إلى GitHub، اعتبره مكشوفاً حتى
> بعد المسح. التغيير هو ما يحمي، لا الحذف.

## أداة استعلام الإنتاج (`prod-db.example.php`)

سكربت مؤقت يُرفع على السيرفر لاستعلام قاعدة الإنتاج، لأن
`sql*.infinityfree.com` لا يُحل خارج شبكة الاستضافة.

### قبل الرفع

1. انسخه إلى `prod-db.php` (بدون `.example`).
2. ضع رمزاً عشوائياً فريداً مكان `PUT_YOUR_OWN_TOKEN_HERE`.
3. ارفعه بـ `deploy-ftp.bat`.

### الاستخدام

```
https://your-domain.com/backend/prod-db.php?token=<TOKEN>&do=<command>&limit=20
```

| `do=` | النتيجة |
|---|---|
| `counts` | عدّاد لكل جدول |
| `users` | آخر المستخدمين وحالة التوثيق |
| `users_by_role` | تجميع حسب الدور |
| `entities` | آخر الجهات مع الصور |
| `services` | الخدمات وطول الحقول المخصصة |
| `sql` | استعلام `SELECT` / `WITH` حر |

### الحماية المدمجة

| الإجراء | التفصيل |
|---|---|
| قراءة فقط | يرفض `UPDATE` / `DELETE` / `INSERT` / `DROP` / `ALTER` / `TRUNCATE` / `CREATE` / `GRANT` |
| رمز سري | `hash_equals` ضد timing attacks |
| حد استخدام | `USAGE_LIMIT` استدعاءً ثم **يحذف نفسه** |
| بلا أسرار | يقرأ الاتصال من `.env` على السيرفر |

### بعد الانتهاء

احذف `prod-db.php` من السيرفر عبر FTP أو لوحة التحكم.
