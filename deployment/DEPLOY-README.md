# النشر إلى السيرفر عبر FTP — أداة بضغطة واحدة

## الاستخدام

انقر نقراً مزدوجاً على **`deploy-ftp.bat`**. That's it.

المتطلبات: لا شيء يُثبَّت — الملف يستعمل `curl.exe` الموجود أصلاً في ويندوز.

---

## كيف يعمل

| المرحلة | التفصيل |
|---|---|
| 1. الإعدادات | يقرأ `ftp-credentials.cfg` |
| 2. فحص الاتصال | يتأكد من الوصول للسيرفر قبل أي رفع |
| 3. تنظيف الكاش | `artisan config/route/view/cache/optimize:clear` — حتى لا تُرفع ملفات كاش قديمة تكسر السيرفر |
| 4. مقارنة | يقارن كل ملف مع `.ftp-deploy-state.tsv` (بصمة SHA-1) |
| 5. الرفع | الدفعات من 40 ملفاً، في اتصال واحد، مع إعادة محاولة تلقائية |

**النشر التزايدي (الافتراضي):** يرفع الجديد والمتغيّر فقط.
الملفات التي لم تتغيّر تُتخطّى، فالنشر التالي يستغرق دقائق لا ساعة.

---

## الخيارات

| الأمر | الوظيفة |
|---|---|
| `deploy-ftp.bat` | نشر تزايدي (الافتراضي) |
| `deploy-ftp.bat -Full` | رفع كل الملفات (تجاهل ملف الحالة) |
| `deploy-ftp.bat -DryRun` | عرض ما سيُرفع فقط — بلا أي رفع |
| `deploy-ftp.bat -Force` | رفع الكل وتجاهل ملف الحالة |
| `deploy-ftp.bat -SkipVendor` | بدون مجلد `vendor` |
| `deploy-ftp.bat -NoCache` | بدون تنظيف كاش لارافيل |
| `deploy-ftp.bat -help` | عرض المساعدة |

من سطر الأوامر: `deploy-ftp.bat -DryRun`

---

## الملفات

| الملف | الوصف |
|---|---|
| `deploy-ftp.bat` | نقطة الدخول — انقر عليه نقراً مزدوجاً |
| `deploy-ftp.ps1` | المحرّك (يجب أن يبقى بجانب الـ bat) |
| `ftp-credentials.cfg` | بيانات الاتصال — **لا تشاركه** |
| `.ftp-deploy-state.tsv` | يُنشأ تلقائياً: ما رُفع فعلياً |
| `deploy-logs/` | سجل كل عملية نشر |

**بعد أول نشر تزايدي** لن تحتاج `-Full` إلا إذا أضفتَ مجلدات جديدة —
لأن أي ملف غير مسجّل في ملف الحالة يُرفع تلقائياً.

## ما لا يُرفع أبداً (حماية)

| المستثنى | السبب |
|---|---|
| `.env` | السيرفر له إعدادات إنتاج خاصة به (مفتاح، قاعدة بيانات). رفعه يكسر الموقع |
| `.env.*` | نفس السبب |
| `node_modules/`, `.git/`, `__pycache__/`, `dist/`, `rendered/`, `test-results/` | غير مطلوبة وقت التشغيل |
| `storage/logs/*`, `storage/framework/{cache,sessions,views}/*` | كاش وسجلات — لارافيل ينشئها |
| `*.zip`, `*.log`, `*.tmp`, `*.bak`, `*.traineddata`, `composer.phar` | ملفات ثقيلة أو مؤقتة |
| `check_creds.py`, `check_db.php`, `boot_test.php`, `_inspect_*.php` | **سكربتات تشخيص تكشف بيانات الاتصال** |
| `register_temp*`, `navcheck*`, `test*.cjs`, `admincheck.cjs` | ملفات تطوير |
| `AGENTS.md`, `CLAUDE.md`, `README.md`, `*.yaml`, `Dockerfile`, `package*.json` | توثيق وأدوات لا يحتاجها الإنتاج |

**مهم:** ملفات `.gitignore` داخل مجلدات لارافيل **تُرفع** — هي ما يجعل
`storage/framework/cache/data` و`sessions` و`views` و`logs` موجودة على السيرفر.
بدونها يفشل لارافيل بـ `Please provide a valid cache path`.

## الأداء

- **السريع:** نضع عمليات الرفع في ملف إعدادات `curl` بدل استدعاء curl لكل ملف.
  النتيجة: **351 مللي/ملف** بدلاً من **1255 مللي/ملف** (أسرع 3.6×).
- **الأسماء العربية:** المسار البعيد يُرمَّز بنسبة مئوية، والملف المحلي
  يُكتب بترميز UTF-8. الأسماء مثل `وزارة الرياضة.webp` تصل كما هي.

### زمن أول نشر (كامل)

| العدد | الحجم | الوقت التقريبي |
|---|---|---|
| 10,278 ملف | 336 MB | 60 – 90 دقيقة |
| نشر تزايدي (تعديل 20 ملف) | < 1 MB | 10 – 30 ثانية |

> السيرفر يردّ `230-Your bandwidth usage is restricted` — النطاق محدود.
> أول نشر كبير قد يستغرق وقتاً أطول.

## استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `فشل الاتصال بالمضيف` | تحقّق من `ftp-credentials.cfg` ومن حالة الاستضافة |
| `لا يوجد ملف حالة` | طبيعي في أول نشر — كل الملفات جديدة |
| فشل بعض الملفات | راجع `deploy-logs\deploy-YYYYMMDD-HHMMSS.log` |
| تغيير كلمة المرور | حدّث `ftp-credentials.cfg` ثم أعد النشر |

### ملفات اختبارية على السيرفر

 أثناء الاختبار تركتُ مجلدَي `__probe` و`__probe2` داخل `htdocs/backend`،
وملف `__arabic_test.webp` في `public/images/uploads`.
سيرفر InfinityFree **يمنع أوامر FTP للحذف** (`DELE`/`RMD` ترد 550)،
لذا احذفها من FileZilla أو من لوحة التحكم.

---

## ملاحظة أمنية

`ftp-credentials.cfg` يحتوي كلمة المرور بنص صريح. أضِفه إلى `.gitignore`
(تمّ إضافته بالفعل) ولا ترفعه إلى أي مستودع. للنشر الحقيقي،
غيّر كلمة مرور FTP من لوحة InfinityFree.
